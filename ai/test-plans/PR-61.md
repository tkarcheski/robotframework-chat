| Requirement | In diff? | Where |

| `semantic_equivalence` proposition kind | yes | `equivalence.py` `SEMANTIC_EQUIVALENCE` |
| `SemanticEquivalenceGate` builds prop, casts votes, reads recomputed verdict | yes | `gate()` / `gate_or_replay()` |
| **No reimplemented voting math** — delegates to `jurycore` | yes | calls `store.recompute_verdict` / `store.replay_by_fingerprint`; all majority/abstain/tie/quorum rules live in `jurycore/aggregate.py` |

## Adversarial focus — can a false auto-serve happen? (13 probes, all PASS)

The committed `test_equivalence.py` covers the mandated cases. This plan adds an adversarial layer beyond it (probes run, not committed — they are a verification artifact, not new coverage, since the existing suite is already thorough):

| # | Hazard probed | Result |
|---|---|---|
| a1–a3 | Forge served `semantic_hit` via **direct** `CacheDecision(...)` with `verdict="false"` / `verdict=None` / `quorum_met=None` / `quorum_met=False` / `verdict="undecided"` | all **raise** — `not self.quorum_met` correctly rejects `None` |
| a4 | Forge via **`dataclasses.replace()`** re-typing a candidate → `semantic_hit` with a non-cleared verdict | **raises** (`__post_init__` runs on the new frozen instance) |
| a5 | `semantic_candidate` with `served=True` | **raises** (suggest-only invariant) |
| b | `semantic-suggest` / default / `exact-only` on unanimous true+quorum | **never serves** (`semantic_candidate`, served=False, advisory verdict recorded) |
| c | `semantic-auto-serve` + true + quorum | serves `semantic_hit` |
| d | below-quorum / tie (deny-on-tie) / false / all-abstain | stay `semantic_candidate (served=False)` |
| e1 | cross-**project** candidate | not served; **voters polled 0 times** |

| edge | empty panel | **raises** at construction |
