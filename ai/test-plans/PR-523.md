# Test Plan — PR #523: Redis-backed answer cache for `client.generate()`

- **PR:** #523 (`feat/522-answer-cache`) · **Closes:** #522
- **Under test:** `src/rfc/answer_cache.py` (`AnswerCache`, `CachingProvider`,
  `is_deterministic`) + the `create_provider` / `_maybe_wrap_with_cache` wiring
  in `src/rfc/llm_client.py`.
- **Posture:** adversarial. This is a *measurement harness*; the safeguards
  (correct cache key, deterministic gate, provenance, fail-open) are the point.
  A silently-wrong key = silently-wrong measurements, so key correctness is the
  highest-risk surface.
- **Constraint verified:** tests use `fakeredis` only — **no live Redis, no
  live LLM**. Confirmed (`tests/test_answer_cache.py` imports `fakeredis`;
  `UnreachableRedis` test double; `FakeProvider` test double).

## Intent check

Does the diff resolve #522? Yes — it adds an opt-in
(`ANSWER_CACHE_ENABLED=1`), deterministic-only, provenance-recording,
fail-open Redis memoization of `client.generate()`, wired through
`create_provider` so both `Ask LLM` and grading inherit it. Matches the issue's
four design constraints (opt-in / deterministic-only / provenance / skip-and-log).

## Cache-key correctness (highest risk) — per-param sensitivity matrix

Requirement: **every** output-affecting param must independently change the
key. Missing any = silent wrong answers = FAIL.

| Param | In key? | Independently changes key? | How verified |
|---|---|---|---|
| `model` | yes (`_KEY_ATTRS`) | yes | parametrized `test_each_output_affecting_param_changes_the_key` |
| `base_url` (endpoint) | yes | yes | same |
| `temperature` | yes | yes | same |
| `max_tokens` | yes | yes | same |
| `seed` | yes | yes | same |
| `top_p` | yes | yes | same |
| `top_k` | yes | yes | same |
| `num_ctx` | yes | yes | same |
| `response_format` | yes | yes | same |
| `prompt` | yes (payload) | yes | `test_prompt_changes_the_key` |
| provider type | yes (`type(client).__name__`) | yes | `test_provider_type_changes_the_key` |
| `ANSWER_CACHE_VERSION` | yes (namespace) | yes | `test_version_namespace_changes_the_key` |
| `keep_alive` | **no** (excluded) | n/a | **intentional** — `keep_alive` controls VRAM residency / model-unload timing (`ollama.py` `payload["keep_alive"]`), not answer content. Correctly excluded; including it would over-fragment the cache. |

Extra adversarial key checks (executed manually, all pass):
- Key is `rfc:answer_cache:<version>:<64-hex sha256>`; stable across processes
  (canonical JSON, sorted keys).
- Type-distinct values do **not** collide: `seed=1` (int) vs `seed="1"` (str)
  yield different keys (canonical JSON preserves type).
- `make_key` is called on the **unwrapped** inner client in
  `CachingProvider.generate`, so `provider_type` reflects the real provider,
  not `CachingProvider`.

## Deterministic gate

| Case | Expected | Verified |
|---|---|---|
| `temperature==0`, no seed | cached | `test_temperature_zero_is_cached` |
| `temperature>0`, no seed | **not** cached | `test_nondeterministic_request_is_not_cached_by_default` |
| `temperature>0`, seed set | cached | `test_seeded_nonzero_temperature_is_cached` |
| `temperature>0`, no seed, `ANSWER_CACHE_NONDETERMINISTIC=1` | cached | `test_nondeterministic_override_enables_caching` |

Adversarial note (robustness nit, not a defect): `is_deterministic` uses
`temperature == 0`. A string `"0"` would read as non-deterministic, but the
`Set LLM Parameters` keyword coerces `temperature` to `float` before it reaches
the client, so the supported Robot path is safe. Direct Python callers passing
a string would merely *under-cache* (never wrong answers).

## Provenance

| Case | Expected | Verified |
|---|---|---|
| Cache HIT | `last_metrics['cache_hit'] == True` | `test_hit_sets_provenance_flag` |
| Cache MISS | `cache_hit` falsey | `test_miss_does_not_set_cache_hit_true` |
| End-to-end through `Ask LLM` | `cache_hit` reaches `emit_rfc_data('llm_metrics', …)` | code trace: `Ask LLM` reads proxied `self.client.last_metrics` → emitted. Confirmed reachable. |
| Provenance writable on real `OllamaClient` | no error | manual: `_record_hit(OllamaClient())` sets `cache_hit` OK |

Latent risk (noted, not failed): `_record_hit` only *adds* `cache_hit`; nothing
clears it on a later miss. Safe today because `OllamaClient.generate`/
`OpenAIClient.generate` reassign `last_metrics` every call (verified: a miss
after a hit shows no stale `cache_hit`). A future provider that mutates
`last_metrics` in place could leak a stale hit flag.

## Transparency / proxying — and the `isinstance` caveat

| Case | Expected | Verified |
|---|---|---|
| Attribute read proxy | `wrapped.model`, `wrapped.num_ctx`, arbitrary method | `test_caching_provider_proxies_attributes` |
| Attribute write proxy | `wrapped.model = x` mutates inner | `test_caching_provider_proxies_attribute_writes` |
| Full provider surface present | every `LLMProvider.__protocol_attrs__` reachable | `test_caching_provider_exposes_full_llm_provider_surface` |

**`runtime_checkable` isinstance caveat — assessment for `create_provider`
callers:** `isinstance(wrapped, LLMProvider)` is `False` (proxy attrs resolved
via `__getattr__` aren't seen by `Protocol.__instancecheck__`). I audited every
`create_provider` caller (≈40 sites): **none** runs `isinstance(result,
LLMProvider)`. The only `isinstance(..., LLMProvider)` checks live in
`tests/test_llm_client.py` / `tests/test_openai_client.py` and test the raw
clients, not the wrapper. **Conclusion: the flagged caveat is benign for
`create_provider` callers** — not a real problem.

**However** there is a *separate, real* transparency defect (see below):
`keywords.py` gates five keywords on `isinstance(self.client, OllamaClient)`
(concrete class), which a `CachingProvider` also fails.

## Regression surface

- Cache OFF by default: `create_provider` with `ANSWER_CACHE_ENABLED` unset
  returns the bare client — covered by the deterministic-gate / wiring tests and
  the unchanged full suite (3564 passed in PR evidence).
- Five `keywords.py` keywords (`Wait For LLM`, `Unload Model`,
  `Get Running Models`, `LLM Is Busy`, `Set LLM Endpoint`) branch on
  `isinstance(self.client, OllamaClient)`. With the cache **on**, the client is
  a `CachingProvider`, so these silently degrade (no-op / wrong branch). New
  regression test added: `test_caching_provider_breaks_ollamaclient_isinstance`.

## Negative cases

- Unreachable Redis must fail *open* (covered above), never raise into a test.
- Non-deterministic request must not be served a stale cached answer (gate
  covered above).

## New tests added by this plan

`tests/test_answer_cache.py::test_caching_provider_breaks_ollamaclient_isinstance`
— documents/locks the `isinstance(CachingProvider, OllamaClient) is False`
behavior that disables ollama-management keywords when the cache is enabled.
This is a *characterization* test pinning current behavior and linked to the
filed defect issue.

## Verdict

See PR comment. Core cache safeguards: **PASS**. One real transparency defect
filed as a `from:testing` issue (ollama-management keywords silently disabled
under `ANSWER_CACHE_ENABLED=1`).
