## Intent check

Issue #422 asks for: (a) worktree-per-branch topology so concurrent roles do
not fight over one checkout, (b) per-role git identities, (c) submodule
ownership with mechanical enforcement, (d) explicit emit/watch communication
contracts per role.

| Requirement | In diff? | Where |
|---|---|---|
| Worktree topology + sharing protocol | yes | `ai/GIT.md`, role prompts |
| Per-role identities (worktree-scoped) | yes | `ai/GIT.md` table, session ritual |
| Submodule ownership table | yes | `ai/GIT.md`, mirrored in `scripts/check_submodule_ownership.py` |
| CI enforcement of ownership | yes | `submodule-ownership` job in `.github/workflows/robot-tests.yml` |
| Emit/watch contracts | yes | "Your peers & signals" in all four `.claude/agents/*.md` |
| `engineering` no longer checkout-in-place | yes | engineering.md step 4 |
| `test-design` no longer `gh pr checkout` in place | yes | test-design.md step 3 |

**Intent verdict (static):** the diff addresses every bullet of #422. The only

### Known limitations (documented, not defects)

- Identity is config-based; an agent committing under a non-`@agents.rfc`
  email is indistinguishable from a human. Acknowledged in `ai/GIT.md`
  ("identity-by-config is v1"; per-role tokens are listed as future hardening).
- Guard runs only on `pull_request` events; direct pushes bypass it. Covered
  by the "every merge requires a human via PR" rule in the same contract.
