## Adversarial focus — is the delegation real, or reimplemented voting?

Read every line of `jurygrading/`. The grader's `grade()` does exactly three things: `store.add_proposition(kind=ANSWER_CORRECTNESS, …)`, loop `store.cast_vote(...)`, `return store.recompute_verdict(prop_id, quorum=self.quorum)`. There is **no** tally, majority, tie, or quorum arithmetic anywhere in `jurygrading/` — `grep` confirms the only numeric logic is the `quorum < 1` / empty-panel guards in `__init__`. Majority / abstain-excluded(num+denom) / deny-on-tie / quorum all live in `jurycore/aggregate.py::recompute_verdict`. **Delegation confirmed.**

## Regression surface — #47 interaction

PR #47 changes `jurycore.replay_by_fingerprint`'s tiebreak from `ORDER BY created_at, id` to a new monotonic `insert_seq`, for the case of **multiple propositions sharing one fingerprint within the same second**. #50's grader produces exactly one proposition per `grade()` call; its replay tests (R1–R3) each pin and replay a single proposition, so no duplicate-fingerprint tiebreak is ever exercised — the result is deterministic under either ordering. The 84-test run is green on #50's current (pre-#47) `jurycore`, confirming #50 does **not** depend on the buggy behavior. **#50 is not blocked on #47.**
